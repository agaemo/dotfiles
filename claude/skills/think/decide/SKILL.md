# Decide — Pros Consリストで決める・比較する

具体的な選択肢を渡すと、それぞれのメリット・デメリットを整理する。

```
SKILL_DIR = スキル起動時に提供される "Base directory for this skill:" のパス
```

## このスキルでできること・できないこと

**向いている入力:**
- 2〜3個の具体的な選択肢を比較したい（例：「転職するか今の会社に残るか」「AプランかBプランか」）
- 決め手にしたい条件がすでにある、または一緒に整理したい

**向いていない入力（受け付けない）:**
- 1つの提案・計画のリスクを多角的に検証したい → six-hats（decideは選択肢同士の比較、six-hatsは1つの対象の多面的検証）
- 新しいアイデアの発想が目的 → idea
- 「なぜ」を繰り返して根本原因を探るのが目的 → root-cause
- 相反する要件の両立を考えたい → triz
- 選択肢そのものがまだ無い曖昧な相談 → dialogue

---

## 引数の処理

- **引数あり**: 入力の適切性を判定する（下記参照）
- **引数なし**: 「何と何を比較しますか？」と一言聞く
- **`{verbosity}`**: think から渡される。渡されていない場合は 標準 とする

### 入力の適切性判定

**NG判定の条件（1つでも該当したら断る）:**
1. 選択肢が1つも示されていない、または1つしかない
2. 1つの提案・計画そのもののリスクを多角的に検証したいのが目的（比較ではなく単体評価）
3. 新しいアイデアの発想が目的
4. 相反する要件の両立が目的

NGの場合は「〇〇が目的であれば `<スキル名>` が向いています。」と1文で伝えてSTOP。1に該当する場合は「比較したい選択肢を教えてください」と聞いてWAIT_FOR。

OK判定の場合のみ、以降のステップに進む。以降、選択肢群を `{input}` と呼ぶ。

---

## ブリーフィング（補足情報収集）

`{verbosity}` に関わらず、決め手にしたい条件が `{input}` に含まれていない場合のみ聞く:

「決め手にしたい条件はありますか？（コスト・時間・好みなど。無ければ『なし』でも構いません）」

WAIT_FOR: ユーザーの回答。`{criteria}` として保持する（「なし」「スキップ」の場合は `{criteria}` = ""）。

---

## ステップ1: 整理

選択肢ごとに Pros（良い面）・Cons（悪い面）を洗い出す。

- `{criteria}` が空でない場合: 各選択肢について `{criteria}` の観点での評価コメントを1行添える
- `{criteria}` が空の場合: Pros/Consのみ提示する

IMPORTANT: 「どちらがいいか」の結論は代わりに出さない。整理した材料をもとに、最終判断はユーザーに委ねる。

---

## ステップ2: 出力

| verbosity | 会話上の出力 | ファイル保存 |
|---|---|---|
| 簡潔 | 選択肢ごとのPros/Consを箇条書きのみ | なし |
| 標準 | Pros/Cons＋`{criteria}`評価コメント | 保存先を聞く |
| 詳細 | Pros/Cons＋評価コメント＋各項目の根拠説明 | 保存先を聞く |

`{verbosity}` = 標準 / 詳細 で保存が必要な場合は `{SKILL_DIR}/../SKILL.md` の「出力の整形・保存」の手順に従う。保存時は `{SKILL_DIR}/templates/report.md` を使う。

---

## ステップ3: 対話

- 「他の条件でも見て」→ 追加の `{criteria}` で再評価
- 「選択肢を追加して」→ 選択肢を追加してステップ1からやり直す
- 「多角的にリスクも見たい」→ six-hats への連鎖を提案
- 「終わり」→ 簡潔に締める
- その他 → 整理した材料をもとに対話を継続する
