# Idea — アイデアを出す

新しい案・改善案を発想する。変形・改良する既存の対象があるかどうかで、ブレストとSCAMPERの2つの発想法を使い分ける。

```
SKILL_DIR = スキル起動時に提供される "Base directory for this skill:" のパス
```

## このスキルでできること・できないこと

**向いている入力:**
- 「〇〇のアイデアを出してほしい」という新規発想
- 「〇〇をどう改善できるか」という課題起点の提案生成
- 「既存の〇〇をもっと良くしたい」という変形・発展

**向いていない入力（受け付けない）:**
- 既存の提案を検証・評価したい → six-hats
- 選択肢を比較したい → decide
- 矛盾・トレードオフを解消したい → triz
- 「なぜ」を繰り返して根本原因を探りたい → root-cause

---

## 引数の処理

- **引数あり**: 入力の適切性を判定する（下記参照）
- **引数なし**: 「どんな課題や状況についてアイデアを出しますか？」と一言聞く
- **`{verbosity}`**: think から渡される。渡されていない場合は 標準 とする

### 入力の適切性判定

**NG判定の条件（1つでも該当したら断る）:**
1. 具体的な提案・計画の検証が目的（→ six-hats）
2. 選択肢の比較が目的（→ decide）
3. 矛盾・トレードオフの解消が目的（→ triz）
4. 根本原因の深掘りが目的（→ root-cause）

NGの場合は「〇〇が目的であれば `<スキル名>` が向いています。」と1文で伝えてSTOP。

OK判定の場合のみ以降に進む。以降、発想対象を `{input}` と呼ぶ。

---

## モード判定

- 変形・改良する既存の対象が明確に含まれている（例：「既存のサブスクサービスをもっと良くしたい」）→ `{mode}` = SCAMPER
- それ以外（ゼロからの新規発想、対象が漠然としている）→ `{mode}` = ブレスト

---

## ブリーフィング（補足情報収集）

`{verbosity}` = 簡潔 の場合はスキップしてステップ1に進む。
`{verbosity}` = 標準 / 詳細 の場合、以下を1問だけ聞く（詳細のときのみ2問目も聞く）:

1. 制約はありますか？（予算・期間・技術など。無ければ「なし」）
2.（詳細のみ）誰のため、何のためのアイデアですか？

WAIT_FOR: ユーザーの回答。「スキップ」の場合は該当項目を空のまま進める。`{constraints}` `{purpose}` として保持する。

---

## ステップ1: 発想

### `{mode}` = ブレスト の場合

1. **5W1H**で状況を分解する（Who/What/When/Where/Why/How）。`{purpose}` があれば Why の軸に反映する
2. ブレインストーミングの4原則（批判しない・自由奔放歓迎・質より量・結合改善）に従い、`{constraints}` を踏まえつつ発散的にアイデアを生成する。目安6〜10案
3. アイデアが6件以上出た場合、KJ法の要領で似た発想をグルーピングし、各グループに共通テーマの見出しをつける（6件未満の場合はグルーピングせずそのまま次に進む）

視点軸の例（偏りを防ぐため複数軸から出す）: ユーザー視点／技術・手段視点／ビジネス・運用視点／逆張り視点（あえて逆をやったら）

### `{mode}` = SCAMPER の場合

以下7軸それぞれについて `{input}` の対象を変形するアイデアを出す（軸ごとに1〜3案、無理に全軸埋めなくてよい）:

| 軸 | 問い |
|---|---|
| S（代替） | 素材・人・プロセス・場所・提供形態を置き換えたら？ |
| C（結合） | 異なる機能・目的・分野と組み合わせたら？ |
| A（適応） | 他業界・自然界・別の事例から借用したら？ |
| M（変更・拡大縮小） | 大きく/小さく/形/頻度/順序を変えたら？ |
| P（転用） | 全く別の用途・ユーザー・場面に使ったら？ |
| E（削除・簡略化） | 何を取り除いてシンプルにできるか？ |
| R（逆転・再配置） | 提供者と受益者、順序、中心と周辺を入れ替えたら？ |

IMPORTANT: 発想段階では良し悪しを評価しない。アイデアを広げることだけが役割。

---

## ステップ2: 出力

生成した案が出力数（簡潔=3〜5案）を超える場合、以下の基準で絞り込む: `{constraints}` に違反していないか／視点軸・SCAMPER軸に偏りがないか／実行可能性があるか。

| verbosity | 会話上の出力 | ファイル保存 |
|---|---|---|
| 簡潔 | 案タイトル＋一文説明のリスト（3〜5案） | なし |
| 標準 | 案タイトル＋2〜3文説明（グループ/軸ラベル付き） | 保存先を聞く |
| 詳細 | 上記＋各案の実行ステップ | 保存先を聞く |

`{verbosity}` = 標準 / 詳細 で保存が必要な場合は `{SKILL_DIR}/../SKILL.md` の「出力の整形・保存」の手順に従う。保存時は `{SKILL_DIR}/templates/report.md` を使う。

---

## ステップ3: 対話

- 「案Nを深掘りして」→ その案の詳細・実行ステップを展開
- 「別の角度から出して」→ 未使用の視点軸・SCAMPER軸があればそれで再生成
- 「このアイデアのリスクは？」→ six-hats への連鎖を提案
- 「終わり」→ 簡潔に締める
- その他 → 生成したアイデアを踏まえて対話を継続する
