# Root Cause — 5つのWhyで原因を掘る

「なぜ？」を繰り返し問い、表面的な対処ではなく繰り返し起きる問題の根本原因にたどり着く。

```
SKILL_DIR = スキル起動時に提供される "Base directory for this skill:" のパス
```

## このスキルでできること・できないこと

**向いている入力:**
- 「なぜこの問題が繰り返し起きるのか」という根本原因への疑問（例：「なぜいつも締め切り直前にバタつくのか」）
- 表面的な対処ではなく、問題の元を掘りたい

**向いていない入力（受け付けない）:**
- 「既存のXをもっと良くしたい」（変形・改良が目的 → idea）
- 「AとBのどちらが良いか」（比較検証が目的 → decide、多角的な検証なら → six-hats）
- 「相反する要件を両立したい」（矛盾解消が目的 → triz）

---

## 引数の処理

- **引数あり**: 入力の適切性を判定する（下記参照）
- **引数なし**: 「どんな問題について、なぜを掘り下げたいですか？」と一言聞く
- **`{verbosity}`**: think から渡される。渡されていない場合は 標準 とする

### 入力の適切性判定

**NG判定の条件（1つでも該当したら断る）:**
1. 掘り下げるべき問題・事象が何も含まれていない
2. 既に解決策が決まっており改良・改善のみが目的
3. 選択肢の比較・意思決定が目的

NGの場合は「〇〇が目的であれば `<スキル名>` が向いています。」と1文で伝えてSTOP。

OK判定の場合のみ以降に進む。以降、掘り下げる問題を `{input}` と呼ぶ。

---

## ブリーフィング（補足情報収集）

`{input}` に「いつから／どんな時に起きているか」の情報が含まれていない場合のみ聞く:

「いつから、またはどんな時に起きている問題ですか？」

WAIT_FOR: ユーザーの回答。`{input}` に追記する。すでに含まれている場合はこの質問をスキップする。

---

## ステップ1: なぜを連鎖させる

`{input}` に対して「なぜ？」を最大5回連鎖させ、1つ前の答えに対して次の「なぜ？」を重ねる形で根本原因まで掘り下げる。

- 各段階の答えは、事実・伝聞から言えることと、そこからの推論を区別する。推論が含まれる場合は文末に「（推定）」と明記する
- 3〜5段階目あたりで、これ以上「なぜ」を重ねても本人の行動や仕組みでは変えられない領域（社会構造・他者の意思決定など）に達したら、そこで打ち切って「これ以上は本人の行動・仕組みで変えられない領域」と明記する
- 根本原因に到達したら、そこから導ける「次の一手」を1〜2個添える

IMPORTANT: 「なぜ」の連鎖を代わりに断定しない。事実確認が要る段階は「（要確認）」と明記し、ユーザーに検証を促す。

---

## ステップ2: 出力

| verbosity | 会話上の出力 | ファイル保存 |
|---|---|---|
| 簡潔 | なぜ1→…→根本原因の連鎖のみ | なし |
| 標準 | 連鎖＋次の一手 | 保存先を聞く |
| 詳細 | 連鎖＋次の一手＋各段階の（推定）/（要確認）の根拠説明 | 保存先を聞く |

`{verbosity}` = 標準 / 詳細 で保存が必要な場合は `{SKILL_DIR}/../SKILL.md` の「出力の整形・保存」の手順に従う。保存時は `{SKILL_DIR}/templates/report.md` を使う。

---

## ステップ3: 対話

- 「ここは違う、実際は〇〇」→ 該当段階を修正し、そこから先を再度掘り下げる
- 「この原因を解決する案が欲しい」→ idea への連鎖を提案
- 「対策を比較したい」→ decide への連鎖を提案
- 「終わり」→ 簡潔に締める
- その他 → 掘り下げた内容をもとに対話を継続する
