# Structure — 頭の中を整理して伝える

ロジックツリー（要素分解・全体像把握）とピラミッドストラクチャ（結論から伝える）で、話や考えを整理する。

```
SKILL_DIR = スキル起動時に提供される "Base directory for this skill:" のパス
```

## このスキルでできること・できないこと

**向いている入力:**
- 頭の中がごちゃごちゃした話・考えを整理したい（例：「新規事業の検討事項が多すぎて頭の中がぐちゃぐちゃ」）
- 人に説明・報告するために結論から筋道立てて話したい（例：「上司に施策を提案する話を整理したい」）
- 全体像を漏れなく把握したい

**向いていない入力（受け付けない）:**
- 新しいアイデアの発想が目的 → idea
- 選択肢の比較・意思決定が目的 → decide
- 根本原因を掘りたい → root-cause
- 相反する要件の両立を考えたい → triz
- 方向性そのものがまだ定まっていない曖昧な相談 → dialogue

---

## 引数の処理

- **引数あり**: 入力の適切性を判定する（下記参照）
- **引数なし**: 「何を整理したいですか？」と一言聞く
- **`{verbosity}`**: think から渡される。渡されていない場合は 標準 とする

### 入力の適切性判定

**NG判定の条件（1つでも該当したら断る）:**
1. 新しいアイデアの発想が目的
2. 選択肢の比較・意思決定が目的
3. 「なぜ」を繰り返して根本原因を探るのが目的
4. 相反する要件の両立が目的
5. 方向性・答えそのものがまだ定まっていない曖昧な相談

NGの場合は「〇〇が目的であれば `<スキル名>` が向いています。」と1文で伝えてSTOP。

OK判定の場合のみ、以降のステップに進む。以降、整理対象を `{input}` と呼ぶ。

---

## ブリーフィング（補足情報収集）

- `{verbosity}` = 簡潔 の場合: ブリーフィングをスキップし、ステップ1に進む
- `{verbosity}` = 標準 / 詳細 の場合: 「誰に、何のために伝えるものですか？（社内共有・上司への提案・自分の頭の整理 など）」と一言聞く。WAIT_FOR: ユーザーの回答。「スキップ」と返答された場合は `{audience}` = "" とする

`{audience}` が空でない場合、以降の生成で誰向けかを踏まえる。

---

## ステップ1: モード判定と生成

`{input}` の性質から `{mode}` を判定する。

- 「モレなく分類したい」「要素を洗い出したい」「全体像を把握したい」→ `{mode}` = ロジックツリー
- 「結論から話したい」「人に説明・提案したい」「筋道立てて伝えたい」→ `{mode}` = ピラミッドストラクチャ
- 判定に迷う場合はピラミッドストラクチャを選ぶ（伝達目的のほうが日常では多いため）

### `{mode}` = ロジックツリー の場合

`{input}` の主題を根に置き、MECE（モレなくダブりなく）を意識しながら2〜3階層に要素分解する。

### `{mode}` = ピラミッドストラクチャ の場合

`{input}` から結論を1文で抽出し、それを支える根拠を3つ程度のグループに整理し、各根拠の詳細を1段掘り下げる（結論→根拠グループ→詳細の3階層）。

### 共通: MECEチェック

生成した構造に対し、「重複している要素はないか」「抜けている要素はないか」を一言で自己点検し、気になる点があれば出力に添える。

IMPORTANT: 判断・結論そのものを代わりに出さない。整理された構造を提示し、最終判断はユーザーに委ねる。

---

## ステップ2: 出力

| verbosity | 会話上の出力 | ファイル保存 |
|---|---|---|
| 簡潔 | 構造の要点のみ（インデント箇条書き） | なし |
| 標準 | 構造全体（mermaidまたは箇条書き）＋MECEチェック1行 | 保存先を聞く |
| 詳細 | 構造全体＋MECEチェック＋各要素の背景説明 | 保存先を聞く |

`{verbosity}` = 標準 / 詳細 で保存が必要な場合は `{SKILL_DIR}/../SKILL.md` の「出力の整形・保存」の手順に従う。保存時は `{SKILL_DIR}/templates/report.md` を使う。

---

## ステップ3: 対話

- 「もっと深掘りして」→ 該当する要素だけさらに1階層分解する
- 「別の切り口で」→ ロジックツリー/ピラミッドストラクチャを切り替えて再生成する
- 「アイデアが欲しい」→ idea への連鎖を提案
- 「終わり」→ 簡潔に締める
- その他 → 整理された構造をもとに対話を継続する
