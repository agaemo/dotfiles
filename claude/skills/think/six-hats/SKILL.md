# Six Thinking Hats — 6視点で検証する

Six Thinking Hats（6つの帽子）の視点で、トピック・提案書・意思決定を多角的に検証する。
日常的な軽い検証は単一プロンプトの軽量モードで、しっかり検証したい時は5エージェント並列の精密モードで分析する。

```
SKILL_DIR = スキル起動時に提供される "Base directory for this skill:" のパス
```

## このスキルでできること・できないこと

**向いている入力:**
- 具体的な提案・計画・アイデアの多角的検証（例：「新製品Xを日本市場に投入する計画」）
- 2択以上の選択肢の比較検討（例：「AかBか、どちらのアーキテクチャを採用するか」）
- 意思決定前の論点整理（例：「スタートアップに参画するかどうか」）

**向いていない入力（受け付けない）:**
- 前提条件が未定義の広い問い（例：「何かいいビジネスはないか」「次に何をすべきか」）
- 「答えを1つ出してほしい」という要求 — Six Hatsは答えを導くツールではなく、人間の判断を支援するツール
- 事実調査・検索が必要な問い

---

## 引数の処理

- **引数あり**: まず入力の適切性を判定する（下記参照）
- **引数なし**: 「何を分析するか?」と一言聞く。ユーザーの返答を分析対象とする
- **`{verbosity}`**: think から渡される。渡されていない場合は 標準 とする

### 入力の適切性判定

入力を受け取ったら分析を始める前に以下を判定する。

**NG判定の条件（1つでも該当したら断る）:**
1. 「何かいい〇〇はないか」「〇〇を探している」のように、答え自体の生成を求めている
2. ターゲット・制約・前提条件が何も含まれておらず、問いが広すぎる
3. 「〇〇を教えて」のように情報検索が目的

NGの場合は分析を開始せず、以下を返す：
```
このスキルは「具体的な提案・計画・選択肢」の多角的検証に向いています。
今の入力「{input}」は[NG理由]のため、Six Hatsでの分析には向いていません。

分析するには入力を具体化してください。例：
- 対象を絞る（誰向け？どの市場？）
- 選択肢を持ち込む（A案 vs B案）
- 既存の計画・提案を渡す
```

OK判定の場合のみ、以降のステップに進む。

以降、分析対象を `{input}` と呼ぶ。

---

## モード判定

- `{verbosity}` = 詳細 → `{mode}` = 精密（5エージェント並列＋青帽統合）
- `{verbosity}` = 簡潔 / 標準 → `{mode}` = 軽量（単一プロンプトで6視点をまとめて生成）
- 「精密に」「しっかり検証して」「エージェントで」等の明示指定があれば `{verbosity}` に関わらず `{mode}` = 精密
- 「さっと」「ざっくり6視点で」等の明示指定があれば `{verbosity}` に関わらず `{mode}` = 軽量

---

## ブリーフィング（補足情報収集）

`{verbosity}` に応じて質問数を調整する。優先度順に以下を出力してから WAIT_FOR: ユーザーの回答。
「スキップ」「省略」と返答された場合は `{context}` = "" としてステップ1に進む。

- `{verbosity}` = 簡潔 の場合: 1問のみ
  1. **特に気になっている観点**: すでにリスクや懸念として頭にあるものがあれば
- `{verbosity}` = 標準 の場合: 上記に加えて
  2. **提案・計画の詳細**: 背景・目的・規模感を補足してください（ステークホルダー・予算・期間など）
- `{verbosity}` = 詳細 の場合: 上記に加えて
  3. **意思決定の制約**: 期限・意思決定者・覆せない前提条件などがあれば

ユーザーの回答を `{context}` として保持し、変数 `{enriched_input}` を定義する:
- `{context}` が空でない場合: `{enriched_input}` = `{input}` の末尾に `\n\n## 補足情報\n{context}` を追加したもの
- `{context}` が空の場合: `{enriched_input}` = `{input}`

IMPORTANT: 以降のすべてのエージェント起動では `{input}` の代わりに `{enriched_input}` を使うこと。対話フェーズのagent再起動でも同様。

---

## ステップ1: 分析

### `{mode}` = 精密 の場合: 5エージェントを並列起動

以下の5ファイルをそれぞれ READ し、`{enriched_input}` を置換したプロンプトとして `run_in_background: true` で**同時に** Agent 起動する。全エージェントの完了通知を受け取ってからステップ2に進む。

| ファイル | 帽子 |
|---|---|
| `{SKILL_DIR}/agents/white.md` | 白帽（事実） |
| `{SKILL_DIR}/agents/black.md` | 黒帽（リスク） |
| `{SKILL_DIR}/agents/yellow.md` | 黄帽（価値） |
| `{SKILL_DIR}/agents/red.md` | 赤帽（直感） |
| `{SKILL_DIR}/agents/green.md` | 緑帽（代替案） |

エージェントが失敗した場合は「報告なし」として扱い、青帽の統合で欠損を明記する。

### `{mode}` = 軽量 の場合: 単一プロンプトで6視点を生成

エージェントを起動せず、1回の応答内で以下6視点それぞれの要点を生成する（下表は各`agents/*.md`の着眼点を簡略化したもの。agents/*.mdはREADしない）。

| 視点 | 着目点 |
|---|---|
| 白帽（事実） | 客観的データ・既知の情報・不明点の整理 |
| 黒帽（リスク） | 致命的リスク・見落とされがちな問題・最悪シナリオ |
| 黄帽（価値） | メリット・ベストシナリオ・価値の裏付け |
| 赤帽（直感） | 感情・直感・第一印象（理由づけ不要） |
| 緑帽（代替案） | 新しい可能性・代替案・改善アイデア |
| 青帽（整理） | 上記5視点から見えた明確な点・次に考えるべき問い |

PROHIBITED: 軽量モードでエージェントを起動すること。1回の応答内で完結させる。

---

## ステップ2: 青帽による統合・出力

6視点（精密モードなら5エージェントの結果＋統合、軽量モードなら単一プロンプトで生成した6視点）を受け取り、以下の内容を組み立てる。

IMPORTANT: 会話・保存ファイルのいずれでも分析結果を最初に提示する際は、次の順序で提示すること: 0)「Six Thinking Hatsとは」を一言 → 1) 全体マップ（mindmap）の図 → 2)「用語集」。保存ファイルでは2)の「用語集」を `<details><summary>用語集</summary>` 〜 `</details>` で囲み折りたたみ表示にする（会話上では折りたたみは効かないため通常の箇条書きのままでよい）。

### verbosity に応じた出力

| verbosity | mode | 会話上の出力 | ファイル保存 |
|---|---|---|---|
| 簡潔 | 軽量 | サマリー表のみ | なし |
| 標準 | 軽量 | サマリー表 + 青帽の整理 | 保存先を聞く |
| 詳細 | 精密 | サマリー表 + 青帽の整理 + 各帽子の詳細 | 保存先を聞く |

PROHIBITED: ユーザーの保存先確認なしにファイルを書くこと

verbosity = 簡潔 の場合: ファイル保存は行わない。下記テンプレートの「## サマリー」形式で会話上に出力し、ステップ3（対話）に進む。
verbosity = 標準 / 詳細 の場合、保存が必要な場合は `{SKILL_DIR}/../SKILL.md` の「出力の整形・保存」の手順に従う。保存時は `{SKILL_DIR}/templates/report.md` を使う（`{enriched_input}` の冒頭30字・`{YYYY-MM-DD}` および各帽子の内容を対応する変数に置換）。

ファイル保存後、会話上には「`{実際の保存フルパス}` に保存しました」と一言だけ伝える。
verbosity = 詳細 の場合は詳細セクションも会話上に出力する。それ以外は詳細セクションを会話上には出力しない。

---

## ステップ3: 対話

レポート出力後、以下を受け付ける。

- 「黒帽をもっと詳しく」など特定帽子への深掘り依頼:
  - `{mode}` = 精密 の場合 → {enriched_input}（補足情報を含む分析対象）を置換して該当エージェントを再起動し、補足を生成
  - `{mode}` = 軽量 の場合 → エージェントを起動せず、該当帽子の視点で単一プロンプト内で補足を生成
  - 結果は会話上のみに出力し、ファイルは更新しない
- 「もっとしっかり検証して」「精密モードで見て」→ `{mode}` = 精密に切り替える。ブリーフィングで未取得の質問があれば追加で聞いてから（`{context}` に追記）ステップ1から再実行
- 「別の案を出して」「緑帽に追加を」→ 緑帽の視点で追加案を生成（精密モードはエージェント再起動、軽量モードは単一プロンプト）。結果は会話上のみに出力し、ファイルは更新しない
- 「〇〇の方針で進める場合のリスクは」→ 黒帽の視点で特定シナリオのリスクを生成（精密モードはエージェント再起動、軽量モードは単一プロンプト）。結果は会話上のみに出力し、ファイルは更新しない
- 「終わり」→ 簡潔に締める
- その他の質問・発話 → 青帽として統合的な視点で答える
