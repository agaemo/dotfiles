# Reflect — KPTで振り返る

期間・出来事を渡すと、Keep（続けること）・Problem（課題）・Try（次に試すこと）の3観点で振り返りを整理する。

```
SKILL_DIR = スキル起動時に提供される "Base directory for this skill:" のパス
```

## このスキルでできること・できないこと

**向いている入力:**
- 期間・プロジェクト・出来事の振り返り（例：「今週のスプリントの振り返り」「先月の営業活動を振り返りたい」）
- 経験から次に活かす学びを整理したい

**向いていない入力（受け付けない）:**
- 未来の選択肢の比較・意思決定が目的 → decide
- 新しいアイデアの発想が目的 → idea
- 「なぜ」を繰り返して根本原因を探るのが目的 → root-cause
- 方向性そのものがまだ定まっていない曖昧な相談 → dialogue

---

## 引数の処理

- **引数あり**: 入力の適切性を判定する（下記参照）
- **引数なし**: 「何についての振り返りですか？期間や出来事を教えてください」と一言聞く
- **`{verbosity}`**: think から渡される。渡されていない場合は 標準 とする

### 入力の適切性判定

**NG判定の条件（1つでも該当したら断る）:**
1. 過去の経験・出来事ではなく、未来の選択・意思決定が目的（→ decide）
2. 新しいアイデアの発想が目的（→ idea）
3. 根本原因の深掘りが目的（→ root-cause）

NGの場合は「〇〇が目的であれば `<スキル名>` が向いています。」と1文で伝えてSTOP。

OK判定の場合のみ、以降のステップに進む。以降、振り返り対象を `{input}` と呼ぶ。

---

## ブリーフィング（補足情報収集）

`{input}` に期間・出来事の具体性が乏しい場合のみ聞く:

「期間や出来事をもう少し教えてください（例：いつからいつまで、何をした/何が起きたか）」

WAIT_FOR: ユーザーの回答。`{input}` に追記する。すでに具体的な場合はこの質問をスキップしてステップ1に進む。

---

## ステップ1: 整理

`{input}` から以下の3観点を抽出する。

- **Keep（続けること）**: うまくいった・今後も続けたいこと
- **Problem（課題）**: うまくいかなかった・改善したいこと
- **Try（次に試すこと）**: Problemを踏まえた次の一歩。「〇〇する」という行動可能な粒度にする

情報が不足している観点は無理に埋めず「（情報不足のため省略）」と明記する。

IMPORTANT: 判断・評価を代わりに下さない。本人の経験に基づく振り返りを整理する役に徹する。

---

## ステップ2: 出力

| verbosity | 会話上の出力 | ファイル保存 |
|---|---|---|
| 簡潔 | Keep/Problem/Tryを箇条書きのみ | なし |
| 標準 | Keep/Problem/Try＋各項目の一言補足 | 保存先を聞く |
| 詳細 | Keep/Problem/Try＋補足＋次回に向けた優先順位 | 保存先を聞く |

`{verbosity}` = 標準 / 詳細 で保存が必要な場合は `{SKILL_DIR}/../SKILL.md` の「出力の整形・保存」の手順に従う。保存時は `{SKILL_DIR}/templates/report.md` を使う。

---

## ステップ3: 対話

- 「Tryをもっと具体化して」→ 該当のTry項目を行動可能な粒度まで深掘りする
- 「原因も掘りたい」→ root-cause への連鎖を提案
- 「次どうするか決めたい」→ decide への連鎖を提案
- 「終わり」→ 簡潔に締める
- その他 → 整理した内容をもとに対話を継続する
