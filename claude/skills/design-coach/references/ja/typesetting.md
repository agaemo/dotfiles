# 日本語の文字組み

確認状況: デジタル庁デザインシステムβ版のタイポグラフィ、W3C「日本語組版処理の要件」（JLReq）の冒頭部分、WCAG 1.4.12 を取得して確認済み。JLReq は全文が約54万字で、約物・和欧間アキの具体値の節は未読。

## デジタル庁DS のタイポグラフィ（数値の基準）

- フォント: `'Noto Sans JP', sans-serif`（SIL OFL 1.1、Web フォント利用可）。等幅は `'Noto Sans Mono'`。OS のシステムフォントを使ってもよい
- ウェイト: 通常 400、太字 700（100〜900 の9段階があるが、基本は2つ）
- **サイズ: 本文と UI は 16px 以上が基準**。14px は基本的に使わない（フッターなど限定的な場面）。14px 未満は原則許容しない。見出し・本文は 16〜45px、インパクトが必要な要素は 48〜64px
- **行高**: 読み物の本文は**少なくとも 1.5 倍**。文字が大きい見出しは本文より狭く

| スタイル | サイズ | 行高 | 用途 |
|---------|-------|------|------|
| Display | 64 / 57 / 48px | 140% | ページ上部のヘッドコピー |
| Standard | 45〜16px | 140〜175% | 見出し・本文。**16〜17px の本文は 170〜175%**、18px は 160%、20〜26px は 150% |
| Dense | 17 / 16 / 14px | 120% または 130% | データテーブルなど表示領域に制約がある画面。**120% は情報量を最優先する業務画面、130% は管理画面** |
| Oneline | 17 / 16 / 14px | 100% | ボタンなど1行のテキスト |
| Mono | 17 / 16 / 14px | 150% | コード |

- 字間: Standard の 36px 以下は 1〜2%。Display、Dense は 0
- CSS の行高は**単位なしの数値**（例: `1.7`）で書く
- イタリック: 日本語フォントはイタリックを持たず、傾けた疑似体になり読みにくい。理由がなければ避ける
- テキスト装飾: リンクは下線が標準。**標準のテキスト装飾の変更や取り消しは、アクセシビリティ上推奨されない**

## 基準から外してよい場面（経験則。デジタル庁DS に明記はない）

LP・ブランドサイトで、基準と異なる値を使うときは、**理由を仕様に書く**。

- 超大型ディスプレイ（欧文 1〜4文字、1行のみ）: 行高 1.0 前後でよい（行間が発生しないため）。和文の複数行には使わない
- 2行で収まる短い日本語の見出し: 行高 1.25〜1.35 に詰めてよい。3行以上になる場合は 1.4 以上
- 装飾のラベル（欧文の大文字・番号）: 14〜15px でよい。ただし情報は本文（16px 以上）が担い、`h2` などの見出し要素は 16px 以上にするのが安全
- 14px のキャプション・注記・チップは、限定的な用途に絞り、コントラストを必ず実測する（暗い面の上でも 4.5:1）

## 業務画面での使い分け

- 密度優先の画面（データテーブル、管理画面）は Dense（行高 120〜130%）。**本文を 14px にするのは、情報量が最優先の場合に限る**
- 読み物（説明文、ヘルプ、規約）は Standard（16〜17px、行高 170% 前後）
- ボタン、タグ、バッジなど1行の UI は Oneline

## WCAG との関係

- 1.4.12 テキストの間隔（AA）: 利用者が行間 1.5 倍、段落後 2 倍、字間 0.12em、語間 0.16em に上書きしても、**内容や機能が失われない**こと。作者がこの値を適用する義務はない
  - 設計: テキストの入れ物を固定高さにしない（切れる・重なる）。省略記号（…）を使うなら、全文を見る手段を用意する。コンテナの寸法は em で指定すると推奨される
  - **日本語は語間や段落後の間隔を使わないため、その言語で使う属性だけで適合できる**（例外）
- 1.4.10 リフロー（AA）: 幅 320 CSS ピクセル（= 1280px の 400% ズーム）で、二次元スクロールなしに読める。データテーブル、地図などは例外（`a11y/wcag.md`）

## JLReq（日本語組版処理の要件）から確認できたこと

- 漢字・平仮名・片仮名は、原則として字間を空けずに並べる**ベタ組**。ベタ組以外に、字間を一定量空けるアキ組、詰める詰め組がある
- **行長は、文字サイズの整数倍**に設計する（基本版面の設計）
- 約物の配置（句読点・括弧）、**行頭禁則、行末禁則**、始め括弧類の行頭への配置などの規定が存在する。具体的な規則と数値は未読
- 和欧文混植の節（全角の欧字・数字、縦中横、プロポーショナル欧字）が存在する。具体的な量は未読
- 縦組は右から左へ行が進み、右綴じ。横組は左から右、左綴じ。縦組の英数字は、正立、90度回転、縦中横の3通り

折り返し（MDN で確認）:
- `text-wrap: balance` は、各行の文字数をなるべく均等にする。見出し・キャッチなど短いテキスト向け。Baseline 2024。**適用は Chromium で 6 行以下、Firefox で 10 行以下**
- `text-wrap: pretty` は、長めの本文で、行末に少数の文字が孤立するのを減らす（処理は遅い）
- `word-break: auto-phrase` は、文節の途中で改行しない。**実験的で、対応ブラウザは未確認**
- 手動で文節を区切る（`<wbr>` など）のは経験則

Web 実装の目安（出典未確認の経験則）:
- 行長: 和文 35〜45 字程度が読みやすいとされるが、一次資料で未確認
- 約物の詰め・禁則は、ブラウザが標準で `line-break` と `word-break` で扱う。厳密にしたい場合は `line-break: strict` や `text-spacing-trim` などを確認する（未確認）
- 和文の見出しは、`font-feature-settings: "palt"` で詰めて見せる手法がある（未確認。本文には通常使わない）
