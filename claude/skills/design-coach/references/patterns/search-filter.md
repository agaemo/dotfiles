# 検索とフィルタ

## 原則

「探す」手段は、**キーワード（検索）**と**絞り込み（フィルタ）**の2系統。どちらを主にするかは、利用者が探すときに言葉を思いつけるか、条件で絞りたいかで決まる。

## 適用ルール

### 検索ボックス
- トップページや一覧画面では、検索を**リンクではなく入力欄（ボックス）**として置く。人は「文字を入力できる小さな箱」を探してスキャンするため。NN/g の事例では、トップページの検索をリンクからボックスに変えて、検索の利用が **91%** 増えた
- 位置は**ページ上部**。通常は右上が適し、左上でもほぼ同等（NN/g）
- 全ページから使えるようにする。利用者がいつ迷うかは予測できない（NN/g）
- 一般的な検索語が収まる**十分な幅**にする。狭いと入力が横スクロールして使いにくい（NN/g。具体的な幅の数値は記載なし）
- 下層ページで、デザインがシンプルなら検索リンクでもよい。複雑なページはボックスを使う（NN/g）
- 虫眼鏡アイコンやボタンの扱いは、取得した記事に記載なし（別記事「The Magnifying-Glass Icon in Search Design」で要確認）

### フィルタとファセット
- **フィルタ**: 条件に合わないものを除外する仕組み全般
- **ファセット**: 複数のフィルタを軸として並べた構造。軸が多く柔軟で、コンテンツ全体の姿を見せられる。一方、構築・保守が高コスト（全コンテンツに各ファセットのメタデータが必要）で、利用者の理解・操作の負担も増える（NN/g）
- 単純なフィルタ（例: 形式別のタブ）は、**利用者が重視する軸と一致している場合にだけ**役立つ。大規模で多様な軸が必要なときにファセットが有効
- ファセットへの投資前に、**利用者が本当に必要としているか**を確認する（NN/g）
- 業務一覧では、**ステータスごとに画面を分けず、1つの一覧に状態フィルタを付ける**のが拡張しやすい（経験則）

### 一覧画面での配置（Carbon の例）
- 検索は、ツールバーに**折りたたみ式**（アイコンで開く）または**常時表示**（テーブルのタイトル下、左側）。複雑なフィルタはツールバー（Carbon。詳細仕様の記載なし）
- **有効なフィルタがあること**を視覚的に示す（NN/g データテーブル記事）

### 経験則（出典未確認）
- 適用タイミング: 件数が少ない・応答が速いならその場で反映。重い検索や複数条件は「適用」ボタン
- 件数: 結果件数を表示し、フィルタ適用後の件数が分かるようにする
- クリア: 有効なフィルタを、まとめて解除できる操作を近くに置く
- 0件: 条件の調整案を示す（`patterns/empty-states.md`）
- 状態の保持: 詳細画面から戻ったとき、検索・フィルタ・ソート・ページ位置を保持する（URL のクエリで表現できると共有・再現しやすい）

## 失敗例

- 検索がアイコンだけ、または小さなリンクで見つからない
- ステータス別に一覧画面を分けて、画面が増える
- 絞り込み中であることが分からず、「データがない」と誤解される
- 詳細から戻ると、条件がリセットされる
