# 権限・無効状態・監査ログ

確認状況: **大部分が経験則で、出典の確認が足りない。** 確認できたのは NN/g の「無効ボタン」に関する要約（検索結果のスニペット）と、デジタル庁 DS-670.1 の脅威例のみ。権限による表示制御（隠すか無効にするか）を直接扱う一次資料は取得できていない。断定せず「要確認」として扱う。

## 確認できていること

- 無効なボタンは、**押せそうに見えて何も起きない**ため混乱を招く。使うのは控えめにし、アクセシビリティを確保し、**なぜ無効なのかを説明する**（NN/g の動画紹介の要約）
- 無効状態には `aria-disabled="true"` を付けるとよい。これで、キーボードフォーカスは受けつつ、スクリーンリーダーに非活性であることを伝えられる（NN/g「Button States」の要約）
- 使用エラーで特定すべき脅威に、「**適切な権限のない利用者による機能変更**」が含まれる（デジタル庁 DS-670.1 4.1.1）
- 権限エラーの空状態では、**アクセス申請の手順**を示す（Carbon の空状態パターン）

## 経験則（要確認）

### 隠すか、無効にするか
| 状況 | 方針 |
|------|------|
| その操作の存在を、利用者が知らなくてよい（役割上無関係） | **隠す** |
| 条件を満たせば使える（権限申請、前提の入力、状態の変化） | **無効にして、理由と解決策を添える** |
| 存在を知らせること自体が情報漏えいになる | **隠す**（サーバー側でも拒否する） |

- **UI で隠す・無効にするのは、セキュリティ対策ではない**。必ずサーバー側で権限を検査する
- 無効にするなら、ツールチップや隣接テキストで**理由**を示す（NN/g の方針に沿う）
- 権限がない画面に直接アクセスされたときは、「権限がない」ことと**次の行動**（申請先）を示す

### 状態に応じた制御
- 状態（承認済みなど）によって操作できないものは、無効 + 理由、または非表示（状態の説明がオブジェクトの詳細にあることが前提）
- 他の人が編集中、期限切れなどの競合は、**誰が・いつ**を示す

### 監査ログの表示
- 最低限の項目: **誰が・いつ・何を（対象とアクション）・変更前後**
- 対象オブジェクトの詳細画面に、時系列の履歴として置く（OOUI の「対象に関する情報を、対象の中に」）
- 利用者向けの履歴（変更履歴）と、管理者向けの監査ログ（全操作）は分ける
- 日時は、タイムゾーンを明記する
- 変更前後は、差分が分かる形（変更した項目だけ強調）

## 失敗例

- ボタンを隠しただけで、API は誰でも呼べる
- 無効ボタンの理由が分からず、「壊れている」と思われる
- 権限エラーで「403」だけを表示する
- 履歴に「更新しました」とだけ書かれ、何が変わったか分からない
