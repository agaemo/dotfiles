# キーボード操作

確認状況: 基準（2.1.1、2.1.2、2.4.7、2.4.11）は W3C で確認済み（`a11y/wcag.md`）。業務システムのショートカットの設計は NN/g のヒューリスティクス7 と経験則。

## 最低限（WCAG）

- すべての機能がキーボードだけで操作できる（2.1.1）。マウスだけの操作（ドラッグ、ホバー専用）には代替を用意する（2.5.7）
- フォーカスが見える（2.4.7）。固定ヘッダーなどで**隠れない**（2.4.11）。表示は隣接色と 3:1 以上（1.4.11）
- キーボードトラップを作らない（2.1.2）。**モーダルは意図的にフォーカスを閉じ込めてよいが、Esc と閉じるボタンで抜けられる**
- Tab の順序を、画面の読み順に合わせる。見た目の順と DOM 順を別にしない
- モーダルを開いたらフォーカスをモーダル内へ、閉じたら開いた要素に戻す（経験則）
- ボタンは Enter と Space の両方に反応する（慣習。ARIA ルール3）

## 業務システムの効率化

- **継続的に使う人**向けに、よく使う操作へのショートカットを用意する（NN/g「柔軟性と操作効率」）
- ショートカットは**発見できる**ようにする（ツールチップ、メニューにキー表示、`?` で一覧）（経験則）
- ブラウザ・OS・支援技術と衝突するキーを避ける（Ctrl/Cmd + 英字は特に注意）（経験則）
- 一覧は、↑↓で行移動、Space で選択、Enter で開く、が慣習的（経験則）
- フォームの Enter: テキストエリアでは改行、Ctrl/Cmd + Enter で送信、など挙動を決めて統一する（経験則）
- OOUI: 一覧 → 詳細、詳細 → 一覧への移動を、キーボードだけで完結できるようにする
