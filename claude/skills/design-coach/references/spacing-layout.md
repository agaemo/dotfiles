# 余白・レイアウト・階層

エンジニア向けの対応: 余白は「魔法の数字の排除」。スケールを決め、そこからだけ選ぶ。

## 余白のスケール（4px または 8px 基準）

| 名前 | 値 | 典型用途 |
|------|---|---------|
| 1 | 4px | アイコンと文字の間 |
| 2 | 8px | 小部品の内側、密な要素間 |
| 3 | 12px | |
| 4 | 16px | カード内、フォーム要素間 |
| 6 | 24px | カード間、セクション内のブロック間 |
| 8 | 32px | |
| 12 | 48px | セクション内の大ブロック間 |
| 16 | 64px | セクション間（業務系） |
| 24 | 96px | セクション間（LP・ブランド系） |

スケール外の値（13px、18pxなど）を使わない。

## 原則

- **近接**: 関連するものは近く、無関係なものは遠くに置く。余白の差でグループが見える。区切り線に頼る前に、余白で分ける
- **余白は内側 < 外側**: 要素のまとまりの内側の余白より、まとまり同士の間の余白を大きくする
- **余白は「足りない」より「多すぎる」方が失敗しにくい**。迷ったら広げる（ただし業務系で情報密度が必要な画面は例外）
- **一貫性**: 同種の要素は同じ余白にする。ずれると「雑」に見える

## 視覚的階層

画面で最も重要な要素から順に、**サイズ・ウェイト・コントラスト・余白・位置**で優先度を付ける。

- 各画面に**主役は1つ**。主役が複数あると視線が迷う
- 主要操作（CTA）は1画面1つを基本にし、副次操作は見た目を弱める（アウトライン/テキストリンク）
- 目を細めて（ぼかして）見て、主役が分かるかを確認する（スクイントテスト）

## グリッドとレイアウト

- 12カラムグリッドが標準。ガターは 16〜32px
- コンテンツ幅の上限: 読み物 640〜720px、業務画面 1200〜1440px、LP 1100〜1280px（背景は全幅、中身は上限幅）
- **Zパターン**（LPなど）: 左上ロゴ → 右上ナビ → 斜めに視線 → 下部のCTA
- **Fパターン**（文章の多いページ・一覧）: 左上から横に読み、左端に沿って縦に降りる。重要な情報は左上と左端に置く
- 整列: 要素の左端（和文は左揃え）を揃える。中央揃えは短い見出し・CTAにのみ使い、長文は左揃え

## 単調さを避ける（均等3カラムの回避）

AIが出しがちな「同サイズのカードが3列」を避けるには:
- カードの**サイズに差**を付ける（1つを大きく、他を小さく）
- 非対称のレイアウト（7:5 の2カラムなど）
- 画像/図とテキストを左右交互に配置
- 余白の広いセクションと密なセクションを交互にして**リズム**を作る
- 枠線とカードを減らし、**余白と背景色の面**でグループを作る

## レスポンシブ

| ブレークポイント | 幅 |
|----------------|---|
| sm | 640px |
| md | 768px |
| lg | 1024px |
| xl | 1280px |

- モバイルファースト（狭い幅から設計し、広い幅で拡張）
- モバイルは1カラム、余白は左右 16px。タップ領域は、WCAG 2.2 で **AA が 24px 角以上（間隔で代替可）、AAA が 44px 角以上**。重要な操作は 44px を目指す（`a11y/wcag.md`）
- 狭い幅で消す要素を事前に決める（隠すのではなく優先度を下げる）
- テーブルは狭い幅で横スクロール、またはカード型に変換する

## 角丸・影・境界

- 角丸は**スケール化**（例: 4 / 8 / 12 / 16 / 9999）。ネスト時は「外側 = 内側 + 余白」にする
- 角丸の大きさが印象を決める: 小=端正・真面目、大=親しみ・柔らかさ
- 影は**多用しない**。使うなら奥行きの段階（浮いている度合い）で2〜3段階に固定し、色は黒でなく背景色に寄せた透明度の低い色にする
- 境界線は1px、色は背景より少し濃いニュートラル。境界と影の併用は避ける

## よくある失敗

- 余白の値が不規則
- すべてのブロックが同じ間隔で、グループが見えない
- 主役が複数、または主役がない
- 中央揃えの長文
- カードの入れ子（カード内にカード内にカード）
