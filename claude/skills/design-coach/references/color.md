# 色

エンジニア向けの対応: 色は「役割ごとの変数」。値を直接書かず、役割（primary / surface / text-muted / danger など）に名前を付ける。

## 構成の基本

- **60-30-10**: 60% ドミナント（背景・大面積）/ 30% セカンダリ（カード・セクション）/ 10% アクセント（CTA・重要箇所）
- アクセントは「少ないから目立つ」。多用すると何も目立たなくなる
- 色の役割は固定する: プライマリ（主要操作）、セマンティック（成功・警告・エラー・情報）、ニュートラル（背景・文字・境界）。同じ意味に別の色を使わない

## パレットの作り方

1. **ブランド/アクセントの1色**を決める（業種慣習に従うか、意図的に外すかも決める）
2. その色の明度違いを **50〜900 の約9段階**で作る（薄い背景 → 濃い文字まで）
3. **ニュートラルは純グレーにしない**。アクセントの色相に寄せた、彩度の低い色（例: ブルー寄りのグレー、ウォーム寄りのグレー）にするとまとまりが出る
4. セマンティック色（成功=緑 / 警告=黄橙 / エラー=赤 / 情報=青）を用意する。**色相は慣習どおり**にする（エラーは赤）
5. 主要な組み合わせのコントラスト比を計算する

## コントラスト（WCAG）

| 対象 | 最小比 |
|------|-------|
| 本文テキスト | **4.5:1**（必須扱い） |
| 大きい文字（18pt=24px 以上、または 14pt 太字≈18.7px 以上） | 3:1 |
| 比率は丸めずに比較する | 4.499:1 は 4.5:1 を満たさない（WCAG 1.4.3。詳細は `a11y/wcag.md`） |
| UI部品の境界・アイコン・フォーカスリング | 3:1 |

計算式（相対輝度 L）:
- 各チャンネル `c = 値/255`、`c <= 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`
- `L = 0.2126*R + 0.7152*G + 0.0722*B`
- 比 = `(明るい方L + 0.05) / (暗い方L + 0.05)`

確信がない場合は推定値と明示する。実測できるなら計算スクリプトを書く、またはブラウザの開発者ツールで確認する。

## 色だけに意味を持たせない

エラー・状態は**アイコンやテキストと併用**する。色覚多様性への配慮であり、白黒印刷でも通じる。グラフは色以外に形・ラベル・パターンも使う。

## ダーク/ライト両対応

- 背景を完全な黒（#000）にしない。深い色（例: #0F1520）にする。純黒+純白は眩しく目が疲れる
- ページ背景とカード背景の**区別がつく明度差**を確保する（数値の出典なし。経験則として、境界が必要な部品は隣接色と 3:1 以上。`a11y/wcag.md`）。暗くしすぎると境界が消える
- ダークでは影が効きにくい。**面の明るさの差（elevation）**で奥行きを出す（手前ほど少し明るくする）
- ダークでは彩度の高い色が強く見えすぎる。アクセントは**少し彩度を落とす/明度を上げる**
- ライトの値をそのまま反転しない。両テーマ用にトークンを別定義する
- 実装は CSS 変数 + `prefers-color-scheme` と手動切替の両方に対応できる形にする（実装は別途依頼）

## 業種の慣習

- 金融=青・信頼、医療=青/緑・清潔、食=暖色・食欲、環境=緑、といった慣習がある
- 慣習に従うと**安心感**が出る。外すと**記憶に残る**が、誤解のリスクも出る。どちらかを意図して選び、理由を記録する

## 配色のパターン

- モノトーン+1アクセント: 最も安全。表現は引き締まる
- 類似色（隣り合う色相）: 穏やか・調和
- 補色/トライアド: 活気・遊び。面積の比率を大きく偏らせる（10%に絞る）
- 背景に色を敷く: 全面ベタよりも、**淡いグラデーション/トーンの異なる2〜3面**で変化をつけると単調さが減る

## よくある失敗

- 理由なき青（#3B82F6 など）のプライマリ
- グレースケールだけで構成し、個性がない
- 彩度が高い色を大面積に使い、目が疲れる
- ニュートラルが純グレーで、色との相性が悪い
- 薄いグレーの文字を薄いグレー背景に置く（コントラスト不足）
