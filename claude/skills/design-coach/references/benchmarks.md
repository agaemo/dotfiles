# ベンチマーク分析（参考サイトの分解）

「このサイトのようにしたい」と言われたとき、雰囲気の模倣ではなく**要素に分解**して、再現できるもの・できないものを仕分ける。

## 分析手順

0. WebFetch が 403 などで取得できないサイトは、ブラウザ自動化ツールで開く（要約でなく実画面と計算済みスタイルを取れる）
1. ブラウザで開き、PC幅(1440前後)とモバイル幅(390前後)のスクリーンショットを撮る。**画像・動画が読み込まれていない場合は、その旨を明示**し、見えていない部分を推測で語らない。**背景画像が未読み込みのとき、白文字が灰の単色に載って見えるが、これはコントラスト不足の判定に使わない**（実画像での見え方は未確認）。スクロールで切り替わる構造（スライドなど）は、実際にスクロールして切り替わりを確認する（自動送りかスクロール連動かで、モーションと操作の設計が変わる）
2. JavaScript で計算済みスタイルを取得する（可能な場合）
   - `font-family` / 実使用サイズの分布 / 本文の font-size・line-height
   - 使用色の頻度上位（oklch/oklab 形式の場合はそのまま記録し、必要なら sRGB に換算）
   - ページ全体の高さ、セクション数
3. 次の表に分解する

| 層 | 見るもの | 再現可否 |
|----|---------|---------|
| 構成 | 1画面1メッセージか、セクション順、視線の流れ | 可 |
| タイポ | フォント、スケール差、行間、字間 | フォントはライセンス次第。代替で近づける |
| 色 | 地の色、アクセント1色、使用比率 | 可 |
| 余白 | 左右マージン、セクション間隔、グリッド | 可 |
| モーション | スライド切替、スクロール連動、ホバー | 可(実装コスト大) |
| ブランド資産 | ロゴ、モチーフ（図形・線）、キャラクター | **不可（権利・制作物）。モチーフの「使い方の原則」だけ学ぶ** |
| 素材 | 写真・動画・イラストの質と撮り方 | **不可。素材を用意する前提で設計する** |

4. 「再現できる層」「代替で近づける層」「再現できない層」を**正直に**ユーザーへ伝える。再現できない層が品質の大半を占めるサイトでは、そのまま同等にはならないと先に言う

## 観察例: コクヨ（kokuyo.com）トップ

確認できた範囲（スクリーンショットと計算済みスタイル、PC幅のみ。画像は読み込まれておらず、写真・動画は未確認）:
- ファーストビューは**全画面スライド**（3枚）。各スライドは「大きな見出し（左下）+ 1行の補足 + 丸矢印つきリンク + 右下に `n / 3`」のみ。**1画面1メッセージ**
- スライドは**自動送りではなく、縦スクロールで 1/3 → 2/3 → 3/3 と切り替わる**（縦約 2046px の領域に3枚を重ねた構造）。停止ボタンは検出されなかった
- 文字サイズは**画面幅に連動する流体設計**（ルートの font-size が vw 連動。1234px 幅で本文 約14.6px）。固定 px のコンテナではない
- 左右の余白が広く（1434px 幅で左右約160px）、要素は左端に揃え、右端にはページ番号とUIだけを置く
- 地は白〜極薄グレー、文字は黒に近い濃いグレー(oklch 0.27)。アクセントは**明るいライムグリーン**(oklch 0.97 0.07 125 付近)を、お知らせバーのような細い帯にだけ使う
- 欧文は Helvetica Now 系、和文は Tazugane Gothic 系（いずれも商用フォント。Web 配信にはライセンスが必要）
- ロゴ右の「///」（斜線3本）がCIのモチーフとして要所に繰り返される
- 見出しは大きいが、字間は詰めすぎず、ウェイトは中〜太で統一。多色や装飾に頼らない

ここから学べる原則:
- 余白と**抑制**（色数・装飾・文字数を減らす）で上質さを出している
- アクセント色は面積を極小にして、かえって目立たせる
- 小さな固定モチーフ（斜線）で、ブランドの一貫性を全ページに通している
- UI部品（ページ番号、矢印、リンク）の**サイズ・位置・線の太さが統一**されている

再現が難しいもの: 写真/動画のアートディレクション、CI/VIそのもの（モチーフ・ロゴ・専用書体）、スライド切替とスクロール連動の作り込み。
