# ユーザーフローとジャーニー

確認状況: 定義と使い分けは NN/g の記事を取得して確認済み。書き方の型とチェックリストは一般的な経験則。

## 原則

| | ユーザージャーニー | ユーザーフロー |
|---|------------------|---------------|
| 視点 | マクロ（高レベルの目標を、複数チャネル・期間にわたって） | ミクロ（1つの製品内の一般的な課題） |
| 期間 | 数日〜数カ月 | 数分〜数時間 |
| 捉えるもの | 行動・思考・感情・チャネル | 操作とシステムの応答（感情は含まない） |
| 成果物 | ジャーニーマップ | ワイヤフロー、フローチャート、タスク図 |
| 向くリサーチ | フィールド調査、日記調査、インタビュー | ユーザビリティテスト |

併用すると有効: ジャーニーの中で製品を使う場面を、ユーザーフローで掘り下げる。

## 業務系で使うのはユーザーフロー

画面を設計する前に、**主要タスクごとにフローを1本**描く。画面を作る前の確認用であり、画面構成の元（OOUI のビューとナビ）とは別に持つ。

OOUI との関係: 画面構成は対象（名詞）を軸にし、フローは「ある対象に対して、どんな順で何をするか」を確認する。タスクを先に画面にするのではなく、**対象に対するアクションの流れ**として描く。

## 書き方（テキスト形式）

1行に「状態」と「ユーザーの操作」を書き、分岐は括弧で示す。

```
[申請一覧] → 「新規申請」押下 → [申請フォーム]
[申請フォーム] → 入力 → 「申請」押下
  ├ 入力エラー → [申請フォーム]（エラー表示、入力値を保持）
  ├ 成功 → [申請詳細]（状態=申請中、完了メッセージ）
  └ 権限なし → [エラー画面]（次の行動を提示）
```

状態遷移図（画面=状態、操作=イベント）やシーケンス図に近い。mermaid で描く場合は `stateDiagram-v2` か `flowchart` を使う。

## 抜けやすい観点（経験則）

- 入口が複数ある（一覧から、通知から、直接URLから）
- 戻る・キャンセル・中断したとき、入力が消えないか
- エラー（入力、通信、権限、競合・同時編集）
- 空の状態（0件、初回）
- 完了後の着地先（対象の詳細へ）
- 取り消し（Undo）、やり直し

## チェックリスト

- [ ] 主要タスクごとにフローを1本描いた
- [ ] 正常系だけでなく、エラー・空・権限なしを描いた
- [ ] すべてのフローの終点が、行き止まりでなく、次の行動につながっている
- [ ] 入力途中の離脱で、入力が失われない設計か
