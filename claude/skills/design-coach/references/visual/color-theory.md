# 色の設計（OKLCH とデジタル庁DSの構成）

確認状況: MDN「oklch()」とデジタル庁デザインシステムβ版のカラー概要を取得して確認済み。実践のコツ（60-30-10、ダーク対応）は直下の `color.md`（未検証）。

## OKLCH で作る

| 成分 | 意味 | 範囲 |
|------|------|------|
| L | 知覚的な明るさ | 0〜1（0%〜100%）。0=黒、1=白 |
| C | 鮮やかさ | 実用上は約 0.5 以下。**100% = 0.4**（L と違い 100% が 1 ではない） |
| H | 色相角 | 0〜360。`hsl()` と角度の割り当てが違う（0deg は赤でなくマゼンタ寄り） |

- **知覚均等**: L を揃えると、色相が違っても明るさが近く見える。HSL の「明度」とは異なる
- **パレット設計**: L を固定して H を変えると、明るさの揃った色セットができる。同じ H で L を段階的に変えると、明度の階調が作れる
- **ブランド色の派生**: C を下げるとグレーに近づく。ニュートラルをブランド色の色相に寄せたいときに使う
- **ダーク/ライト**: 相対色構文（`oklch(from var(--base) calc(l + 0.15) c h)`）で明度を増減できる。ただし相対色構文は対応状況の確認が必要（`oklch()` 本体は 2023年5月以降、主要ブラウザで利用可能）
- フォールバック: `oklch()` の前に `rgb()` や hex を書く
- Tailwind v4 では `@theme` に `--color-mint-500: oklch(0.72 0.11 178);` のように定義できる（`system/tokens-handoff.md`）
- コントラスト比の計算は WCAG の相対輝度で行う（OKLCH の L の差ではない）。`a11y/wcag.md`

## デジタル庁DSの色の構成（構成の参考）

- **プライマリ**: トーン＆マナーを決める色。CTA、アクティブ状態に使う。**主要な背景色とのコントラスト 4.5:1 以上**
- **セカンダリ**: プライマリと同じ色相で明度を変える。副次的UI。**ターシャリ**: セカンダリと反対の明度
  - 背景・隣接要素として使うなら 3:1 以上、テキストなら 4.5:1 以上
- **ニュートラル**: 白から黒までの **14階調**。テキスト・境界・背景。**テキスト 4.5:1、枠線・ディバイダーは隣接背景に対して 3:1**。ニュートラルに色味を加えてもよい
- **セマンティック**: 成功（緑）・エラー（赤）・警告（黄・オレンジ）。それぞれ明るい/暗いの2段。**色相は保ち**、明度・彩度を調整する（例: エラーを緑にしてはいけない）
- **その他の機能色**: リンクは青（通常）と紫（訪問済み）で 4.5:1。**フォーカスは黄（Yellow-300）と黒の2重**で、変更しない。検索ハイライトはシアンかマゼンタ
- 背景が白・黒以外なら、組み合わせごとにコントラストを確認する

| 対象 | 必要な比 |
|------|---------|
| テキスト（全役割） | 4.5:1 以上 |
| アイコン・枠線・ディバイダー | 3:1 以上 |
| セカンダリ/ターシャリを背景・隣接要素に | 3:1 以上 |

## 設計手順（推奨）

1. ブランド/アクセントの色を1つ決める（OKLCH の H）
2. L を段階的に変えて階調を作る（例: 50〜900）
3. ニュートラルは、ブランドの H に寄せて C を小さくする
4. セマンティック色を、色相を保ったまま用意する
5. 役割ごとに、実際の組み合わせでコントラストを計算する（テキスト 4.5:1、非テキスト 3:1）
6. ダーク用のトークンは、別に定義して確認する
