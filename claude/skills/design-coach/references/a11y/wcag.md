# WCAG 2.2（設計判断に使う達成基準）

確認状況: W3C「Understanding WCAG 2.2」の各達成基準ページを取得して確認済み（下記の出典）。JIS X 8341-3 との対応は一部のみ確認。

レベルは A < AA < AAA。実務の目標は通常 **AA**（JIS X 8341-3:2016 も AA が一般的な目標）。

## 色とコントラスト

| 基準 | レベル | 要件 |
|------|-------|------|
| 1.4.3 コントラスト（最低限） | AA | テキストは **4.5:1 以上**。大きな文字（**18pt = 24px 以上、または 14pt 太字 ≈ 18.7px 以上**）は **3:1**。プレースホルダー、ホバー・フォーカス時のテキストも対象 |
| 1.4.11 非テキストのコントラスト | AA | UI 部品（枠線、チェックマーク、開閉矢印など、存在と操作の識別に必要な視覚情報、状態表示）と、意味を持つ図形（グラフの線、アイコン）は隣接色に対して **3:1 以上** |
| 1.4.1 色の使用 | A | 色を、情報伝達・操作指示・要素の区別の**唯一の手段にしない**。アイコン・テキスト・形・下線を併用 |

- 比率は**丸めずに比較**する（4.499:1 は 4.5:1 を満たさない。2.999:1 は 3:1 を満たさない）
- 例外: 非活性の UI 部品、装飾的なテキスト、ロゴ・ブランド名（ブランドガイドラインに由来する場合）。作者が任意に低コントラストにしたものは例外にならない
- ホバー時の追加表現そのものには 3:1 は求められない。ただし、元の部品のコントラストを下げてはいけない
- 細いフォントはアンチエイリアスで薄く見える。余裕のある色の組み合わせ、または太めのフォントを選ぶ
- リンク: 周囲のテキストと **3:1 以上**で区別する、または下線など色以外の手段を併用する
- 必須項目やエラーを**赤い文字だけ**で示すのは失敗。アイコンや「必須」「エラー」などのテキストを併用する
- グラフ: 系列を色だけで区別せず、ラベル・凡例・パターンを併用する

## ターゲットサイズ（タップ・クリック領域）

| 基準 | レベル | 要件 |
|------|-------|------|
| 2.5.8 ターゲットのサイズ（最低限） | AA | ポインター操作の対象は **24×24 CSS ピクセル以上**。ただし、24px 未満でも、**直径24pxの円を中心に置いて他の対象の円と重ならなければ適合**（例: 20px のボタンを 4px 間隔で配置） |
| 2.5.5 ターゲットのサイズ（強化） | AAA | **44×44 CSS ピクセル以上** |

- 例外: インライン（文章中のリンク）、ブラウザ標準の部品、同等の機能を持つ別の大きな部品がある場合、表示が本質的に不可欠な場合
- 間隔による対応は最低限。ベストプラクティスは、間隔に関係なく 24px を満たすこと。**重要な操作は 44px を目指す**
- ズームでは条件を満たしたことにならない（CSS ピクセルで判定）

## リフローとテキストの間隔

| 基準 | レベル | 要件 |
|------|-------|------|
| 1.4.10 リフロー | AA | 縦スクロールのコンテンツは**幅 320 CSS ピクセル**（= 1280px 幅の 400% ズーム）で、情報や機能を失わず、**二次元スクロールなし**で読める。横書き・縦スクロール以外（縦書き）は高さ 256px |
| 1.4.12 テキストの間隔 | AA | 行間 1.5 倍、段落後 2 倍、字間 0.12em、語間 0.16em に**利用者が上書きしても**内容や機能が失われない（作者が適用する義務はない） |

- 1.4.10 の例外: 地図、図、データテーブル（セルは対象）、操作中にツールバーを出し続ける必要がある UI。例外部分の見出し・検索・ページネーションは例外にならない
- 1.4.12: テキストの入れ物を固定高さにしない。省略記号を使うなら全文を見る手段を用意。**日本語は語間・段落後の間隔を使わないので、使う属性だけで適合できる**（`ja/typesetting.md`）

## キーボードとフォーカス

| 基準 | レベル | 要件 |
|------|-------|------|
| 2.1.1 キーボード | A | すべての機能をキーボードだけで操作できる。経路依存の操作（フリーハンド描画など）は例外。マウスで操作できる全要素がフォーカス可能である必要はなく、同等の操作手段があればよい |
| 2.1.2 キーボードトラップなし | A | フォーカスを移せるなら、キーボードだけで離れられる。Tab や矢印以外で脱出する場合は方法を案内する。**モーダルは意図的にフォーカスを閉じ込めてよいが、閉じる方法（Esc、ボタン）が必要** |
| 2.4.7 フォーカスの可視化 | AA | キーボードフォーカスが**見える**。フォーカス表示は時間で消さない |
| 2.4.11 フォーカスの不可視化回避（最低限） | AA | フォーカスを受けた部品が、作者のコンテンツ（固定ヘッダー、フッター、非モーダルダイアログ、Cookie バナー）で**完全に隠れない** |

- フォーカスインジケータは非テキストなので、1.4.11 により隣接色に対して **3:1 以上**。ブラウザ標準のスタイルを作者が変えていなければ、コントラスト要件は免除（ただし可視であること）
- よくある失敗: フォーカスを受けた直後にスクリプトでフォーカス表示を消す、`outline: none` でフォーカス表示をなくす
- 対策: 固定ヘッダーがフォーカスを隠すなら CSS の `scroll-padding` を使う。モーダル化する。Esc で閉じられるようにする
- カスタムボタンが Enter だけに反応しても基準違反ではない。ただし、ボタンは Enter と Space の両方に反応するのが慣習（ベストプラクティス）
- リッチテキストエディタのように Tab を別の用途に使う部品は、脱出のキー（例: Alt+F10）を案内する

## フォーム・入力

| 基準 | レベル | 要件 |
|------|-------|------|
| 3.3.1 エラーの特定 | A | 入力エラーを自動検出したら、**誤りの項目を特定し、エラーの内容をテキストで説明**する。必須の未入力、形式や範囲の誤りの両方が対象。自動で値を修正した場合も説明する |
| 3.3.2 ラベルまたは指示 | A | 入力を求めるすべての欄（必須・任意とも）に**ラベルか指示**。形式の制約があれば示す。長い指示は、フォーカス時にだけ表示してもよい |
| 3.3.7 冗長な入力 | A | 同じプロセス内で、すでに入力した情報を**再入力させない**（自動入力、または選択可能にする）。例外: 本質的に必要な場合、セキュリティ上の理由（パスワードの再確認）、情報が無効になった場合 |
| 2.5.7 ドラッグ操作 | AA | ドラッグを使う機能は、**ドラッグせずに単一ポインターで**同じ操作ができる（クリックやタップ） |

- 3.3.1: ブラウザ標準の HTML 検証は、汎用メッセージで、拡大されないことがあり、最初のエラーしか伝えないことがある。使う場合は支援技術での動作を確認する。色・アイコン・枠線は補助として使い、**テキストによる説明は必須**
- 3.3.2: `label` 要素でコントロールと関連付ける。見えるラベルがなく `aria-label` だけの場合は、視覚的に分からないため失敗しうる。ラジオやチェックボックスは、各選択肢にラベルを付け、グループは `fieldset` と `legend`
- 3.3.7: 「請求先は配送先と同じ」のチェックボックス、直前の検索語の保持、**エラー時に入力済みの値を消さない**ことが例。ブラウザの自動入力だけでは不十分（コンテンツ側が以前の入力を提供する）。保存する場合は個人情報の保護に注意
- 2.5.7 の代替例: スライダー → 横に数値入力欄やトラックのクリック。並べ替えリスト → 選択して上下ボタン。カンバン → 選択して矢印ボタン、または移動先メニュー。スワイプだけの代替は 2.5.1 に違反する

## 名前・役割・値

4.1.2（A）: すべての UI 部品について、**名前と役割**がプログラムから判別でき、状態・値を設定でき、変化が支援技術に通知される。標準の HTML 部品を仕様どおりに使えば、基本的に満たされる。詳細は `a11y/aria.md`。

## JIS X 8341-3 との関係

- JIS X 8341-3:2016 は国際規格 ISO/IEC 40500:2012（= WCAG 2.0）に対応し、達成基準に A / AA / AAA の適合レベルがある。公開資料では「JIS X 8341-3:2016 (ISO/IEC 40500:2012) 適合レベルAA」と表記する例が見られる
- WCAG 2.2 で追加された基準（2.4.11、2.5.7、2.5.8、3.3.7 など）は、WCAG 2.0 ベースの JIS には含まれないと認識している（**要確認**。JIS の最新版や対応表は未取得）。実務では、JIS の AA を満たしたうえで、WCAG 2.2 の追加分を設計の指針として使うのが現実的
