# 認知負荷と段階的開示

確認状況: NN/g「Minimize Cognitive Load」「Progressive Disclosure」を取得して確認済み。

## 認知負荷

- **内在的**: 内容を理解し、目標を見失わないための負荷。情報を得るために必要で、なくせないし、なくすべきでもない
- **外在的（余計な）**: 理解に役立たず、処理能力を消費するだけの負荷（意味を伝えない装飾的な文字表現など）。**デザイナーが減らす対象**

減らす方法（NN/g）:
1. **視覚的ノイズを避ける**: 重複したリンク、無関係な画像、意味のない装飾。意味のあるものまで排除しない（問題は過剰）
2. **既存のメンタルモデルを使う**: 他サイトで見慣れたラベルやレイアウトを使い、固有の学習を減らす（ヤコブの法則）
3. **タスクを肩代わりする**: 読ませる、覚えさせる、判断させる作業を洗い出して減らす。例: 入力済み情報の再表示、**スマートな初期値**、説明を画像で示す

## 段階的開示（Progressive Disclosure）

最初は重要なオプションだけを表示し、専門的・低頻度の機能は、要求があったときにだけ表示する。

効果: 初心者は重要な機能に集中でき、設定ミスが減る。上級者は使わない項目を探す手間が省ける。学習しやすさ・効率・エラー率を改善する。「全体像が分からなくなる」という懸念は、研究では否定されている。

設計:
- **初期表示と二次表示の振り分けが最重要**。頻繁に使うものは初期表示に。初期表示に項目を詰め込まない
- 二次表示への入口は分かりやすく。ラベルで内容を予測できるようにする
- 機能の選定は、タスク分析、フィールド調査、利用頻度の統計で。アクセス解析だけでは意図的か偶然かを区別できないので、ユーザビリティテストで補う
- **階層は2段階まで**。3段階以上は迷いやすい。必要なら機能の簡素化を先に検討
- 二次機能への経路は**1つ**にする（複数あると初期表示の効率が落ちる）。複数が避けられないならすべてに明確なラベルを

### 段階的開示と、逐次的な開示（ウィザード）

| | 階層的な開示（Progressive） | 逐次的な開示（Staged、ウィザード） |
|---|---|---|
| 移動 | 初期表示から必要に応じて二次表示へ行き、戻る | 直線的に1ステップずつ進む |
| 向く場合 | 初心者が重要な機能に集中する | ステップ同士の依存が小さい |
| 問題になる場合 | 初期表示の判断を誤る | ステップ間を行き来する必要がある |

- ホテル予約の例: 部屋の比較は日付や価格の組み合わせを検討しやすいよう1画面に。支払い情報は検討段階で不要なので後の画面に。**1画面か5画面かの二択ではなく、2画面が最適なこともある**（NN/g）
- ウィザードの詳細は `patterns/wizard.md`

## 業務システムへの適用

- 詳細な検索条件は「詳細検索」として二次表示に。ただし**使用頻度が高い条件は初期表示**にする
- 一覧の列は、既定で重要な列だけを表示し、列の表示切替を用意する（`patterns/tables.md`）
- 設定画面は、基本設定と詳細設定を分ける（詳細設定は1階層まで）

## エンジニア向け補足

段階的開示は、API の「よく使うパラメータを必須引数に、その他を options に」に近い。
