# ブランドの一貫性（モチーフ・トーン・システム化）

上級のデザインは「ページが綺麗」ではなく、**どのページ・どの部品も同じブランドに見える**こと。個別の画面を整える前に、ブランドの共通ルールを決める。

## 決めるもの

1. **ブランドの一言**: 何を約束するブランドか（例: 好奇心、静かな精密さ）。FEEL / ANTI-FEEL の元になる
2. **モチーフ**: 繰り返し使う小さな図形・線・形（斜線、円、角の形、罫線の癖）。1〜2個に絞り、使う場所とサイズを決める（見出し脇、区切り、アイコン、ローディング、背景パターンなど）
3. **トーン**: 文言の口調（です・ます / 体言止め / 問いかけ）、キャッチの長さ、数字の見せ方
4. **UI部品の癖**: ボタンの形、角丸、リンクの下線/矢印、アイコンの線幅とサイズ
5. **色の役割**: 地・文字・アクセントの比率。アクセントを使う場所を限定する
6. **写真・イラストの規則**: 被写体、光、色調、トリミング、余白

## モチーフ設計のルール

- 単純な図形ほど使い回しが効く（斜線・円・四角・点・線）
- 使う場所を限定する。**どこにでも置くと意味が薄れる**
- 向き・太さ・角度を固定する（斜線なら角度を1つに）
- 1つの画面に出す数は少なく（1〜3個）
- ロゴやモチーフは**ユーザー(ブランド)が持つ資産**。既存ブランドの資産を無断で真似たり、似せたロゴを作ったりしない。新規なら提案はするが、確定はユーザーが行う

## デザインシステム化

- トークン: 色・タイポ・余白・角丸・影・モーション時間を名前付きで定義
- コンポーネント: ボタン・リンク・タグ・カード・ナビ・フォームを**状態込み**で定義（通常/hover/focus/無効/エラー）
- 例外を作らない。例外が必要なら理由を記録する
- 実装との接続: CSS 変数（または Tailwind 設定）にトークンを落とし、値を直書きしない（実装は別途依頼）

## 点検

- 3つ以上のページ/画面を並べて、同じブランドに見えるか
- 部品のサイズ・線の太さ・矢印の形・余白が統一されているか
- モチーフが入っている場所を数え、多すぎないか
