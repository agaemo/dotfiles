# 実測の手順（批評・自己点検）

画面の欠陥は、見た目の印象でなく**実測値**で示す。ブラウザ自動化ツールが使えるときの手順。

## ページの計測（ブラウザの JS 実行ツール）

- 非同期処理は、**トップレベルの `await` で書く**（async の即時実行関数を返すと、結果が `{}` になる）
- 取得する値: 本文の `font-size` / `line-height` / 文字色、見出しのサイズとウェイト、14px 未満のテキスト、`a, button` の幅と高さ、`outline` の有無、入力欄のラベル（`labels.length`）、`scrollWidth` と `clientWidth`（横スクロール）
- 狭い幅の確認: 同一オリジンの `iframe`（幅 320px）に読み込み、`documentElement.scrollWidth` を比べる。1.4.10 の例外（データテーブル）は除いて判断する
- 計測結果は、観測した値のまま示す（推測しない）

## コントラスト比（相対輝度）

- 各チャンネル `c = 値/255` → `c <= 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`
- `L = 0.2126R + 0.7152G + 0.0722B`、比 = `(明るい側 L + 0.05) / (暗い側 L + 0.05)`
- **丸めずに比較**する（4.48:1 は 4.5:1 に届かない）。基準は `a11y/wcag.md`

reduced-motion の実動作、スクリーンリーダーの読み上げ、動きの質（感触）、実機の見え方。これらは、人が確認するまで「未確認」と明記する。
