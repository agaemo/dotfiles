# 実測の手順（批評・自己点検）

画面の欠陥は、見た目の印象でなく**実測値**で示す。ブラウザ自動化ツールが使えるときの手順。

## ページの計測（ブラウザの JS 実行ツール）

- 非同期処理は、**トップレベルの `await` で書く**（async の即時実行関数を返すと、結果が `{}` になる）
- 取得する値: 本文の `font-size` / `line-height` / 文字色、見出しのサイズとウェイト、14px 未満のテキスト、`a, button` の幅と高さ、`outline` の有無、入力欄のラベル（`labels.length`）、`scrollWidth` と `clientWidth`（横スクロール）
- 狭い幅の確認: 同一オリジンの `iframe`（幅 320px）に読み込み、`documentElement.scrollWidth` を比べる。1.4.10 の例外（データテーブル）は除いて判断する
- 計測結果は、観測した値のまま示す（推測しない）

## コントラスト比（相対輝度）

- 各チャンネル `c = 値/255` → `c <= 0.03928 ? c/12.92 : ((c+0.055)/1.055)^2.4`
- `L = 0.2126R + 0.7152G + 0.0722B`、比 = `(明るい側 L + 0.05) / (暗い側 L + 0.05)`
- **丸めずに比較**する（4.48:1 は 4.5:1 に届かない）。基準は `a11y/wcag.md`

## 既存プロジェクトの実画面

- 開発サーバーはプロジェクトの方法で起動する（例: `mise exec -- pnpm dev --host 127.0.0.1`）。終了後は**ポートで停止**する（`lsof -ti :<port> | xargs kill`。`pkill -f` は効かないことがある）
- セクションごとの確認: `window.scrollTo({top, behavior:'instant'})` で移動してから撮影する（`scroll-behavior: smooth` のサイトで、撮影前に動き続けるのを防ぐ）。位置は `section` の `getBoundingClientRect().top + scrollY`
- 狭い幅の撮影: 同一オリジンの `iframe`（幅 390px、`position:fixed`）を重ね、`contentWindow.scrollTo` で動かして撮影する。終了時に削除する
- 文字の監査: 文字を持つ要素ごとに、文字色と、**背景色を祖先までたどって**求めた色から比を計算し、基準未満（4.5:1 未満または 14px 未満）を `クラス名|サイズ|比` の1行にまとめる。**出力が長いと切れる**ため、要点だけ返す
- 計測スクリプトは `audit.js`（同じディレクトリ）。文字の監査（コントラスト・サイズ）と孤立行チェックを、貼り付けて実行できる形にしてある
- 監査は、**ページを開いて 2〜3 秒待ってから**行う（色の `transition` や表示アニメーションの途中を測ると、基準未満が誤検出される）
- 監査の結果は「情報を持つ文字」と「装飾（欧文ラベル・番号・プレースホルダー）」に分けて件数を出す。例外のある基準を1つの件数で示さない
- 孤立行: 行頭または行末に1〜2文字だけ残る箇所を、`Range` で1文字ずつ位置を取って探す（`audit.js`）。折り返しは幅で変わるため、複数の幅で行う
- 狭い幅は `resize_window` では測れない（ブラウザのウィンドウに最小幅がある。500px 前後）。390px などは上記の `iframe` を使う
- dev サーバーの CSS がブラウザに古く残り、`getComputedStyle` が編集と食い違うことがある。別ポートで起こし直すと、オリジンが変わって解消する（`localStorage` も空になるので、スクリプトは貼り直す）
- ナビの現在地: 各セクションの先頭へ移動し、ハイライトされている項目を読む（1つ前を指すことがある）
- 後片付け: 起動したサーバー、開いたタブ、重ねた要素を、終了時に停止・削除する
