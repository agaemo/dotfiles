# 改善指示書の形式（批評 → craft への引き渡し）

既存の画面を批評し、実装は craft に任せるときの出力形式。**design-coach は編集しない**。出力先は対象プロジェクトの `.craft/docs/design-improvements.md`（場所と内容の方針を示して了承を得る）。

## 構成

1. **対象と前提**: 対象（パス、URL、ページ）、参照した文書（`CLAUDE.md`、デザインブリーフ）、実測した条件（幅、ツール）
2. **範囲**: 含むもの / 含まないもの / **外部依頼**（写真、文言、価格、URL など、施主や利用者が用意するもの）
3. **改善項目**（1項目につき以下をそろえる）
   - ID、重大度（重大 / 中 / 軽微）
   - 対象: ファイルと箇所（セレクタ、行）
   - 現状: **実測値**（コントラスト比、サイズ、再現手順）
   - 修正: 具体値（既存のトークンから基準を満たすものを先に探し、新しい値は最後）
   - 受け入れ基準: **測定できる形**（例: 「14px 未満の情報を持つ文字が0件」）
   - 確度: 確認済み / 要確認（原因が推測のもの）
4. **適用順**: 依存関係で並べる（トークン → サイズ → 個別の箇所 → ナビなどの挙動）
5. **完了時の検証**: `process/measure.md` の手順で、実測を再実行し、基準を満たしたかを数値で示す
6. **未確認**: 動き、`prefers-reduced-motion`、実機、スクリーンリーダー
7. **craft への依頼文**（1段落）: craft の相談フロー（consult）に、依頼の要約として渡せる形

## 守ること

- 受け入れ基準のない項目を書かない（「見やすくする」で終わらせない）
- 原因が推測のものは「要確認」と書き、修正案を断定しない
- 外部依頼は、実装の項目と混ぜない
- 実装の方法（コード）は書かない。値と基準までを書く
