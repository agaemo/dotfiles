# 種別A: 不具合・障害の原因

共通ルール（編集禁止・根拠と確度・サブエージェントの扱い）は `flows/investigate/SKILL.md` に従う。
SKILL_DIR は呼び出し元で定義済みの値をそのまま使う。

```
1. 症状とエラー情報を整理し、再現手順を組み立てる

2. 再現を試みる
   - コマンド: プロジェクトの CLAUDE.md / README に書かれた起動・テストコマンド
   - 再現用のスクリプトやテストは .craft/ 配下の一時ファイルとして作る
     ツールの制約で置けない場合（例: テストランナーの対象ディレクトリが固定）は、
     対象ディレクトリに新規の一時ファイルとして作る
     いずれの場合も、調査後に自分が作成したファイルだけを削除し、
     ls または git status で残っていないことを確認する
   - 既存のソース・テストは編集しない
   - アプリ起動やテスト実行がローカルのデータを変更しうる場合は、
     SKILL.md のルール「データを変更しうる実行」に従う

3. debugger（{SKILL_DIR}/agents/debugger.md）を起動して根本原因の特定を依頼する
   - 渡すもの: 症状、エラーメッセージ（無い場合は再現で得たログ・失敗箇所）、
     対象プロジェクトの絶対パス
   - プロンプトに必ず追記する制約（省略しない）: 既存ファイルを編集しない／
     データを変更しうるコマンドは実行せず提案に留める

4. 再現できなかった場合:
   その事実と試した手順を根拠に記録し、追加情報（環境・頻度・手順）をユーザーに質問する
   WAIT_FOR: ユーザーの回答
```
