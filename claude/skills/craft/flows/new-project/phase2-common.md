# フェーズ2: 並列トラック共通の注意

全トラックのエージェントが最初に読む。各トラックのプロンプトにはこのファイルへの参照だけを入れ、共通の注意を重複して書かない。

- 設計文書（`.craft/` 配下）は git 管理外のため、worktree にはない。元のプロジェクトルート（プロンプトの `[ORIGINAL_ROOT]`）の絶対パスで読む。
- worktree で最初に、ツールの信頼と依存のインストールを行う（例: `mise trust`、`pnpm install`。`make` 経由が原則）。
- Rust のときは `CARGO_TARGET_DIR` を全トラックで共有する（依存の再コンパイルを避けられる。同時ビルドはロック待ちになる）。
- `make fmt` はプロジェクト全体を整形し、他トラックのファイルを書き換える。トラックの作業では使わず、担当ファイルだけを整形する（例: `rustfmt <file>`、`oxfmt <file>`）。
- コミットメッセージに、作業用の ID（US 番号、トラック名、計画上のステップ番号など）を書かない。何をしたかを書く。
- 【Windows 向けコードがあり、Mac で作業する場合のみ】`cargo check --target x86_64-pc-windows-msvc` で検査する。依存に C のビルドを含むものは対象外。
