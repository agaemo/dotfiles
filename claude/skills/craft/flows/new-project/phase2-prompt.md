実装手順:
1. .craft/docs/stories.md の担当 US の受け入れ条件をすべて読む
2. 依存ファイルを読んで型・インターフェースを把握する
3. 所有ファイルを実装する（所有ファイル以外は絶対に編集しない。共有ファイルは追記のみ）
4. `make build`（Makefileが無い場合は plan.md の「開発コマンド」表に記載のビルド確認コマンド）を実行し、型エラー・コンパイルエラーがないことを確認する
5. 担当 US の各受け入れ条件に対して実装を確認し、満たしていることを確認する
6. 実装した内容を `git add` + `git commit` する（**必須**。コミットされていない変更は後続のマージ工程で失われる可能性がある）

完了基準（すべて満たすこと）:
- `make build` が成功すること
- 担当 US の全受け入れ条件が実装に反映されていること
- 変更が commit されていること

PROHIBITED:
- 所有ファイル以外のファイルを編集すること
- 共有ファイルの既存の記述を削除・変更すること（追記のみ許可）
- DB スキーマ（[スキーマファイルのパス: 例 lib/db/schema.ts]）を変更すること
- フェーズ1の共通コンポーネントを新規作成・変更すること
- **依存ファイルで確定済みのインターフェース（trait・型定義・関数シグネチャ等）に実装が
  素直に適合しない場合、`unsafe`や強引な型変換などで無理に適合させないこと。** その場合は
  実装を止め、完了報告の冒頭に「インターフェース制約により実装できなかった」旨と、
  何が・なぜ適合しないかを明記して報告すること（メインのClaudeが設計を見直す判断をする）。
  やむを得ず`unsafe`を使う場合は、正当化根拠を完了報告に明記すること（レビューで重点確認される）

完了後に報告すること:
- 実装したファイルの一覧
- `make build` 成功の確認
- 受け入れ条件の充足状況（条件ごとに ✅ または ⚠️）
- commit したことの確認（コミットハッシュ・メッセージ）
- 未解決の問題（あれば。`unsafe`使用・インターフェース不適合を含む）
