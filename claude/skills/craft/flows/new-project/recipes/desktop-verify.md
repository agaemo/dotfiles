# デスクトップアプリの自動確認（macOS）

デスクトップアプリ（Tauri・Electron 等）で、ユーザーに実機確認を頼む前に、自動でできる範囲を済ませる手順。macOS 専用。Windows は対象外（実機または CI で確認する）。

## 前提

- ターミナル（Claude Code を動かしているアプリ）に、システム設定の「アクセシビリティ」（キー入力の送信）と「画面収録」（撮影）の権限が必要。権限がないと、キー入力が無視される、撮影が背景だけになる、のいずれかになる。権限がない場合は、ユーザーに付与を依頼する（これ自体は自動化できない）。
- 起動は `make dev` またはビルド済みのアプリを使う。コマンドは `make` 経由が原則。

## 確認の方法

| 確認したいこと | 方法 |
|---|---|
| ショートカットでウィンドウが出るか | `osascript -e 'tell application "System Events" to keystroke "v" using {command down, shift down}'`（キーと修飾キーは実際の設定に合わせる）→ 少し待って撮影する |
| ウィンドウの表示・位置・大きさ | `screencapture -x <out.png>`（全画面）、`-R x,y,w,h`（範囲）、`-l <windowID>`（ウィンドウ指定）。撮影した画像は Read で目視確認する |
| アプリが起動・常駐しているか／前面か | `lsappinfo list`、`lsappinfo front`、`lsappinfo info -only name <ASN>` |
| メニューバー（トレイ）の表示 | メニューバーの該当範囲を `-R` で撮影する |
| 保存されたデータ | DB を直接読む（例: `sqlite3 <db> 'select count(*) from ...'`）。読み取りだけにして、書き込まない。暗号化している内容は表示しない |

## 測定の注意

- 撮影の前に、対象が撮影範囲に入っていることを、1枚撮って確認する。メニューバーの他の項目の変化で範囲がずれ、「0 回中 8 回」のような誤った結果で調査が遠回りになった実例がある。
- 測定の結果が想定と大きく違うときは、まず測定の方法を疑う。
- 画面に実データ（履歴の内容など）が写る場合は、撮影した画像を共有・保存しない。確認が済んだら削除する。

## ユーザーに頼むもの

自動で確認できなかった項目だけを、チェック表にしてユーザーに渡す。例: 見た目の好み、操作感、OS のダイアログ（キーチェーンの許可など）、権限の付与。
