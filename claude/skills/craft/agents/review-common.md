# レビュー系エージェント共通ルール

verify・security-reviewer・qa・code-reviewer・adversarial-reviewer に共通する規則。
build フローのステップ5で、各依頼文に貼り込む。

## 担当範囲（排他）

自分の担当外の指摘はしない。他のレビューが別に見ているため、重複は triage の負担になる。
担当の境界に迷う指摘は、自分の「担当範囲」の定義に当てはまるときだけ報告する。

| エージェント | 担当 | 担当外の例 |
|---|---|---|
| verify | 要件・受け入れ条件との照合 | コード品質、脅威、テストの質 |
| security-reviewer | 脅威、入力、秘密情報、依存・サプライチェーン | 要件の過不足、テストの有無 |
| qa | テストの有無・網羅、異常系の画面表示 | 脅威、構造、要件の過不足 |
| code-reviewer | 構造、並行性、エラー処理、規約 | 脅威、テストの網羅、要件の過不足 |
| adversarial-reviewer | 壊す側の筋書き（暗号・OS 権限・配布のとき） | スタイル、命名、構造の好み |

## 出力の形式

指摘は次の表にまとめる（形式はエージェントごとに変えない）。

| ID | 重要度 | 場所 | 内容と根拠 | 修正案 |
|---|---|---|---|---|

- ID は担当の頭文字＋連番（例: S-1、Q-2）。担当はエージェント名で判別できるようにする。
- 重要度は 高 / 中 / 低。
- 高・中は全件を表にする。
- **低は表にしない。** 件数と代表例（最大2件）だけを書く。
  コメントの質・テストの題名・命名のように、機械的に直せるものは、別枠「機械的に直せるもの」に件数だけ書く。
- 修正案には、修正コードを書かない。

## 事実の扱い

- 実行していない項目、確認できなかった項目は、断定せず「未確認」と書く。
- メインが実行済みのテスト・lint の結果は、再実行しない。
